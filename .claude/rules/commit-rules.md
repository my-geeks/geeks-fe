# Commit Convention

## Format

```
<type>(#<issue>): <message>
```

- `issue`는 관련 GitHub 이슈 번호다.
- `message`는 `git diff`를 분석해 변경 내용을 기반으로 자동 작성한다.
- 한국어로 작성한다.
- 명령문 형태로 작성한다. (예: "버튼 스타일 수정", "로그인 기능 추가")
- 불필요한 부연 설명은 생략한다.

---

## Types

| type | 사용 시점 |
|------|----------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `design` | UI/스타일 변경 (기능 변경 없음) |
| `chore` | 빌드, 설정, 패키지, 기타 잡무 |

---

## Examples

```
feat(#3): 회원가입 폼 유효성 검사 추가
fix(#7): 모바일에서 메뉴가 닫히지 않는 문제 수정
design(#1): 헤더 컴포넌트 반응형 레이아웃 적용
chore(#2): eslint 설정 업데이트
```

---

## Rules

1. `git diff`(스테이징된 변경사항)를 분석해 메시지를 직접 작성한다.
2. 변경된 파일이 여러 type에 걸치면 가장 핵심적인 변경에 맞는 type을 선택한다.
3. 메시지는 50자 이내로 간결하게 작성한다.
4. 커밋 전 `git diff --staged`로 변경사항을 확인하고 type을 결정한다.
